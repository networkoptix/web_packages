Cloud Portal Customization Management System (CMS) Overview

The Customization Management System (CMS) is a cloud service that allows authorized partners to manage an asset with their own branding and content.

Elements that can be customized by a partner from the Cloud Portal CMS include:

•Logos and images

•Default color (for header, footer, background, text, etc.), called the "skin"

•Asset name and company name

•Asset information and summary

•Landing page content

•Display language

•Links for support, emails, company website, etc.

•Download files

•Installation instructions and tutorial

•Requirements and compatibility

 

Assets

There are two types of assets – Cloud Portals and Integrations.

Integration

An innovative hardware or software solution (or combination of both) which utilizes Nx Witness and Powered-by-Nx products.

Cloud Portal

A cloud service that enables simple remote connectivity, streaming, and management of one or an unlimited number of Nx Witness or Powered-by-Nx Systems.

Note: Certain Cloud Portal changes can only be performed by Network Optix directly, or by a partner who has been granted special advanced editing permission.

 

Gaining access to CMS

The first step to using the CMS is to contact Network Optix to arrange for access rights for staff members who will have authority to view, use, or make changes in the customization management system.

 

Registered Cloud Users

The CMS also provides a list of registered Cloud Portal users. Partners with the appropriate access rights can view, sort, filter, and export Cloud user data from this list.                

 

Site Administration

There are two primary levels of authority – Integration Developers and Portal Managers.

Integration Developers

Users in this group can add and edit content, but not publish content.                        

Portal Managers

Users in this group can edit and publish content, and view and download customer account records.

Content Managers

A sub group similar to Portal Managers, but with reduced permissions. Content managers can only edit and submit content for review.

 

Cloud Portal & Integration Update Process

There are three steps to a site update:

1. A Content Manager or Developer enters and previews content changes.

2. When editing is complete, the Content Manager or Developer saves the changes and sends them to a Portal Manager for review. Each set of changes sent for review is assigned a specific Revision number.

3. The Portal Manager reviews and may also edit revisions, then publishes them.

Portal edits can be previewed in draft format at any time without disturbing live pages.

 

Revision Numbering

Sending a set of changes for review generates a numbered Revision (or version) which logs the exact changes made, by whom, and when.

Revision tracking makes it possible to view any published version of the Cloud Portal. Note that the content of revision requests is additive. The Portal Manager receives an email notification for each numbered review request, but only the latest version is shown on the Revisions page of the CMS, and that version will contain all changes that have been sent since the last published update. For example, the current live site is revision 117. Versions 118, 119 & 120 are sent for review but not published. Revision 121, however, is published and will contain all the changes made in versions 118 - 120.

Remember, all updates since the last published set are bundled into the most recent numbered version.
